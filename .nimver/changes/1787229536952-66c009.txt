feat: version sibling manifests together

A repository root can hold several manifests - a .nimble next to a
package.json, or two .nimble files. Nearest-ancestor attribution cannot
tell such siblings apart, so they are resolved as one fixed release unit
and a warning asks for them to be declared in .nimver/config.ini.

`sourceFiles` returns as an optional per-package setting for the cases
nearest-ancestor cannot express, and co-located manifests are rejected
under `strategy = independent`, where separate releases would need an
attribution that does not exist.
