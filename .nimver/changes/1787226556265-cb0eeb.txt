fix: only replace git hooks that carry a generated-by marker

The previous check treated any hook mentioning nimver as generated, so a
hand-written commit-msg or post-commit that calls nimver alongside other
work would be overwritten wholesale - and git shares one hooks directory
across every worktree of a repository, so that loss hits all of them.

Hooks are now replaced only when they carry an exact marker line: ours,
or the one 'nimver install-hooks' writes. Anything else is left alone
with a warning.
