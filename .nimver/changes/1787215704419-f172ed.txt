fix: resolve Git directory paths through git rev-parse

install-hooks assumed the Git directory was literally <root>/.git, so it
failed outright in any checkout where .git is a file pointing elsewhere:
linked worktrees, submodules, and clones made with --separate-git-dir.
isRebaseInProgress made the same assumption and silently returned false
there, letting post-commit amend commits out from under the rebase
sequencer, which aborts the rebase and drops a change note.

Both now ask Git for the path, which also keeps its distinction between
directories shared across worktrees (hooks) and per-worktree state
(rebase-merge, rebase-apply).
